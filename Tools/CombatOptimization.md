# Оптимизация боя — 7 октября 2026

## Что изменено

- Опилки бобра и молнии артефактов переиспользуют экземпляры своих существующих Unity-префабов. Запуск сбрасывает прозрачность, масштаб, возраст, цвет и длительность. В запасе хранится максимум 128 опилок на префаб и 64 молнии; объекты принадлежат текущей сцене.
- Бонус хора лягушек сохраняется для каждой комнаты. Расчёт обновляется при появлении, прыжках, падении, гибели, улучшениях и переносах, а также при первом обращении в новом кадре. Временные списки для вложенных боевых событий переиспользуются; каждый вложенный вызов получает отдельный список.
- Артефакты ищут соседних врагов по клеткам комнаты. Точные проверки расстояния для круга и квадрата сохранены. Появление, перемещение, перенос и удаление врагов сбрасывают сохранённый индекс.
- Полоски ХП обновляют геометрию во время анимации и изменения размеров. Одинаковый текст повторно не назначается. Быстрые попадания одного источника по одному врагу объединяются в сумму за окно 0,12 секунды; разные источники отображаются отдельно. Окно отсчитывается от первой цифры и не продлевается следующими попаданиями.
- Затемнение рассчитывает общие углы соседних квадратов один раз. Неподвижный свет не требует повторного построения. Перемещение, изменение радиуса, перенос и выключение света отмечают комнату для обновления.

## Сравнение

Одинаковые нагрузки в Unity 2022.3.20f1 на этом компьютере, в отдельной копии проекта. Для синхронных расчётов использована медиана трёх повторов после прогрева. Создание эффектов измерялось в 23 сериях по 16 опилок и 16 молний после одной серии прогрева; ожидание между сериями в время не включалось.

| Операция | До, мс | После, мс | Ускорение |
| --- | ---: | ---: | ---: |
| 50 000 запросов бонуса при 64 лягушках | 128,835 | 3,232 | 39,9 раза |
| 10 000 поисков соседей среди 144 врагов | 719,316 | 93,805 | 7,7 раза |
| 20 000 вызовов неподвижной полоски ХП | 20,971 | 0,079 | 266,5 раза |
| 80 построений затемнения с 12 движущимися источниками света | 325,261 | 113,121 | 2,9 раза |
| Запуск 368 опилок и 368 молний после прогрева | 34,950 | 5,356 | 6,5 раза |

Для 384 появлений опилок раньше создавалось 384 объекта, теперь используются те же 16. Для 384 вспышек молний проверено переиспользование 16 объектов.

Это время отдельных операций, не время игрового кадра. FPS, нагрузка видеокарты и производительность на телефоне здесь не измерялись. Счётчик выделения управляемой памяти в этой версии Unity возвращает ноль даже для контрольного массива; его показания исключены из сравнения (`Bytes = -1` означает недоступное измерение).

## Проверки

- Соседние цели совпадают с полным перебором для круга и квадрата. Перемещение обновляет результат в том же кадре.
- Бонус лягушек корректен после переноса хозяина в другую комнату и уничтожения лягушки.
- Урон, лечение и ХП щита сверх максимума сохраняют числа и завершают анимацию полоски.
- Суммирование цифр сохраняет полный урон, префикс яда и разделение источников. Исчезновение старой цифры не удаляет новую группу.
- Движение, изменение радиуса и выключение света обновляют затемнение. Все 2504 вершины проверенной сетки совпадают с точным расчётом прозрачности в пределах точности цвета Unity.
- Все 384 запуска опилок сбрасывают возраст, прозрачность и масштаб. Молния после дуги получает обычную длительность, цвет и новые концы.
- Пройдены 843 проверки артефактов и магазина и 19 проверок бонусного урона лягушек, включая огонь, яд, добивание, избыточный урон и статистику паузы.

Результаты: `CombatPerformanceBaseline.json`, `CombatPerformanceOptimized.json`, `CombatPerformanceValidation.txt`, `ArtifactShopValidationAfterOptimization.txt`, `FrogSupportDamageValidationAfterOptimization.txt` в этой папке.

## Повторение проверки

Основной редактор Unity закрывать не требуется. Проверки запускаются в `obj/FrogValidation`, с отдельными настройками компании и сохранениями.

```powershell
python obj/run_combat_performance_validation.py baseline
python obj/run_combat_performance_validation.py
python obj/run_artifact_validation.py
python obj/run_frog_support_damage_validation.py
```

Режим `baseline` берёт сохранённые версии исходников из `obj/CombatPerformanceBaselineSources`. Для переноса проверки на другой компьютер эту папку нужно сохранить вместе с копией для проверки. Игровые сцены и визуальные префабы продолжают редактироваться обычным способом.
